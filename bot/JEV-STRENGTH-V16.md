# JEV v16 탐색 후보 보강 실험

2026-09-21. 로컬 후보이며 운영은 parallel-v13이다. 앱 버전 1.0.8(64) 유지. 매칭·Elo·게임 규칙은 변경하지 않는다.

## 근거와 범위

v15 최종 개발 실행은 수비형 흑17수 승리·백15수 패배, 전술형 흑12수째 제공사503 중단, 전술형 백 미시작이었다. 더 이른 호위 사용만으로 백 패배를 고치지 못했다. 같은 상대 설정·PRNG시드로 기존 hard 탐색 엔진만 백을 맡긴 별도 로컬 진단은 수비형52수 포획승·전술형50수 목표승이었다. 이는 JEV 성적이나 운영 Elo가 아니며, 계산 예산도 다르므로 직접 승률 우위 통계로 쓰지 않는다.

v16은 첫 JEV 역할 제안이 성공한 뒤 강한 탐색의 후보 하나를 추가한다. 최대4.3초·100,000노드·깊이14 요청 상한이며 실제 완료 깊이와 중단 여부를 기록한다. 재제안과 두 번의 검증을 고려해21초를 먼저 남겨두고 검색 시간을 줄일 수 있다. 재제안 API와 후속 예시의 마감도 남은 턴 예산에 맞춰 줄여 최종 API8초를 확보한다. 짧아진 후속 예시는 같은 깊이로 맞추고 미완료 범위를 명시한다. 같은 턴에서 재제안하더라도 탐색은 한 번만 한다. API503 등 첫 단계 실패에는 실행하지 않는다.

이 후보는 다른 제안과 같은 정확한 즉패·강제패 검사를 거친다. 최종 입력에는 합법 수순 예시와 그 끝의 판, 계산 범위를 제공하며 코드 종합 점수는 넣지 않는다. TT 수순은 다음 미완료 반복이나 bound에서 온 수를 포함할 수 있어 정확한 PV나 강제승패가 아니다. 모든 수를 기존 정식 규칙으로 재생하고 종국·불법·반복·깊이 부족에서 자른다.

JEV가 후보를 거부할 수 있으며 최종 응답 ID를 그대로 적용한다. 최초6역할·5우선순위와 두 API단계는 유지한다. 모델 제안 요청에는 탐색 추천을 먼저 보여주지 않는다. 탐색 후보가 생겼다고 독립 전문가 투표가 늘어난 것으로 해석하지 않는다.

공유AI 변경은 명시적 onContinuation 진단 콜백을 붙이는 것뿐이다. 콜백이 없는 기존 앱·공식봇의 수 선택은 바꾸지 않는다.

## 검증 및 배포 기준

개발 중. 기능 검증과 실제 JEV 기력 검증을 분리하며, engine-only 두 승을 JEV 승으로 보고하지 않는다. 새로운 실제 JEV 개발 대국이 좋아진 뒤 기존 v13과의 미사용시드32판 비교를 통과해야 배포한다. 이전 개발국은 정책 변경 뒤의 독립 검증으로 집계하지 않는다. 원본과 실패 시도도 artifacts/jev/v16에 보존한다.

재생 검사는 v14/v15 이전 기록도 허용하며, v16에서는 탐색 시도 시각·배정 마감·생략 사유, 후보/역할/coverage 연결, 최종 API에 전달된 정확한 briefing을 대조한다. 모의 시계로 첫 API8초와 all-loss 재제안을 거친 뒤 최종8초를 확보하고 전체29.5초에 끝나는 경우를 검증했다.

최종 기능 검사:75파일489테스트·서버타입검사·루트빌드·diff검사 통과.82개 과거 최종 입력에 추가 탐색 자료의 최대 크기 모의값을 넣은 크기 검사는 모두26KB이내(최대25,468bytes)였다. 이 크기용 모의값은 합법 기보나 승리 증거로 사용하지 않았다.
