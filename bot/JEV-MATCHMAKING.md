# JEV 유휴 우선 배정

적용 정책: `idle-priority-v1`, 2026-09-21.

랭킹 실험 기간에 실제 이용자 대국 표본을 확보하기 위해, 봇 대전 요청에서 사용 가능한 JEV를 기존 봇 추첨보다 먼저 배정한다. 기존 방식은 JEV를 후보에 포함하더라도 점수 차이와 추첨 확률 때문에 대기 중인 JEV가 선택되지 않을 수 있었다.

## 배정 조건

1. `MATCHMAKE_BOT` 요청에만 적용한다. `MATCHMAKE`의 사람끼리 매칭은 그대로 유지한다.
2. 실험이 활성 상태이고 만료 전이며 오류 대기 중이 아니어야 한다. JEV 동시 대국은 1개다.
3. 해당 이용자의 직전 봇 상대가 JEV이면 기존 봇을 배정한다. 그보다 이전에 JEV와 대국한 이력은 우선 배정을 막지 않는다.
4. 위 조건을 충족하면 이용자의 Elo와 관계없이 JEV를 배정한다. 충족하지 않으면 기존 봇의 점수대·최근 상대 기반 추첨을 사용한다.

오류로 무효 처리된 대국은 [복구 정책](JEV-RECOVERY.md)에 따라 직전 상대 제한에 남기지 않는다. 기존의 2026-09-25 00:00 KST 만료와 종료 5분 전 신규 매칭 제한도 유지한다. 전략 `parallel-v13`, 복구 `retry-v1`, Elo 계산과 결과 저장은 변경하지 않는다.

`/health`의 `jev.matchmakingPolicy`로 배포된 정책을 확인한다. `acceptingMatches`는 실험의 가용 상태이며, 실제 배정에는 현재 대국 점유 여부와 이용자별 직전 상대 조건도 적용된다.

## 검증

- 800·1500·1800·2400점에서 각각 7,000개 추첨 입력 모두 유휴 JEV를 선택한다.
- 직전 상대가 JEV이거나 JEV가 사용 불가이면 기존 봇 선택 분포와 일치한다.
- 로컬 WebSocket 서버에서 사람끼리 매칭 → 유휴 JEV 우선 배정 → 대국 중 다른 봇 배정 → 같은 이용자의 JEV 연속 대국 제외 → 다른 이용자의 JEV 우선 배정을 확인한다.
- 인증 오류로 JEV가 중단된 뒤에도 기존 봇으로 매칭한다. 기존 일시 오류 복구 검사도 통과했다.

환경은 macOS, Node 20.20.2, 로컬 PostgreSQL 16이다. API 응답은 모의 처리했으며 운영 전적에 시험 대국을 추가하지 않았다.

전체 `npm test -- --maxWorkers=2`는 435/435 통과했고, 서버 타입 검사와 루트 빌드도 통과했다.
