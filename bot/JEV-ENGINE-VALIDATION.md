# JEV 모델링·전술 개선 검증

작성: 2026-09-20. 대상: 임시 랭킹 봇 `침착맨이할때까지`.
앱 버전은 사용자 승인대로 1.0.8(64)을 유지한다. 운영 프로필·Elo를 변경하는 시험 대국은 하지 않았다.

## 실제 패배와 수정 근거

첫 운영 대국은 30ply에 상대 목표 도달로 끝났다. JEV의 15번 착수는 전부 왕 이동이었고 호위는 배치하지 않았다.
실제 응답·기보와 적용 해시는 정상으로 재생됐다. API 장애 때문에 진 판은 아니었다.
27번째 착수에서는 4ply에서 찾은 패배 증명이 재제안의 3ply 결과에 덮였지만, 그 시점 전체 합법 수의 패배도 별도 계산으로 확인됐다.
따라서 이 결함 하나만 고쳐 원래 판을 이길 수 있다고 주장하지 않는다.

수정한 사항:

1. 깊은 탐색의 확정 승패 증거를 재탐색·부분 중단 뒤에도 보존하고, 공통 깊이 평가와 증명 출처를 구분한다.
2. 반복 계산을 캐시하고 이전 탐색의 유력 응수부터 확인한다. 3,000노드 제한의 개발 국면 15개에서 공통 4ply 완료가 4개에서 11개로 늘었다. 시간 측정은 로컬 환경이며 운영 성능이 아니다.
3. 기존 역할 제안 외에 서로 다른 호위 대안을 턴당 최대 두 개 보충한다. 역할별 확률을 합산하지 않고 최종 JEV 선택도 덮어쓰지 않는다.
4. 대표 탐색 수순에 빠진 상대의 호위 배치·왕 추격을 별도로 조사한다. 원본 7수 직전에서 왕 전진 뒤 상대 `p_3_3`은 왕의 옆·뒤 이동만 남기는 압박으로 재현됐다. 최대 1초·2만 노드 안에서 조사하고 누락은 미확인으로 표시한다.
5. `mongjin-briefing-3`은 몽진을 교대 턴의 왕 경주와 호위 전개 게임으로 설명한다. 왕의 비포획, 한 턴 한 행동, 호위의 배치 발판, 포획된 호위의 영구 제거, 상대 응수 뒤 판단을 명시한다. 후보 설명은 말 종류·출발·도착·소비하는 턴을 사람이 읽을 수 있는 문장으로 제공한다. 최종 선택지 옆에는 상대의 실제 압박 응수와 전진·후퇴·호위 대응 수를 직접 요약해 놓고, 미완료 검사 수를 함께 밝힌다.
6. 경로 길이는 정적 추정으로 표시하며, 흑백·다음 차례를 반영한 미래 ply 도달 시점으로 함께 표현한다. 종합 점수를 따라 고르도록 지시하지 않는다.

최종 후보는 `parallel-v9`으로 구분한다. 의사결정 입력은 v7의 `mongjin-briefing-3`으로 복원했고, v4~v8 기보도 재생된다. v6·v8은 실제 대국에서 각각 0승 4패여서 배포 후보에서 제외했다. v8의 공격 분석 모듈은 과거 실험 기록 감사용으로만 유지하고 실전 착수 경로에서는 실행하지 않는다.
종국 증거는 마지막 수순의 실제 승자·종국 사유와 일치하는지 확인한다. 전체 증명 트리를 다시 확장하는 감사는 아니다.
왕 압박 예시는 모든 기록된 대응에 대해 상대 다음 수 종국을 재검사한다. 다음 수 안전을 장기 안전으로 해석하지 않는다.

## 시범 대국 기록

Node 20.20.2, macOS arm64. 로컬 기존 랭킹 봇 `연세대MAY`(1000, 수비형), `うずまき`(1400, 전진형)를 대상으로 흑백을 교환한다.
봇의 표시 Elo는 설정값이며, 이 실험의 대전 실력 척도로 재보정한 값은 아니다.
seed는 상대 난수 순서를 고정하지만 시간 제한 탐색과 JEV 응답의 완전 재현성을 보장하지 않는다.
초기 실패 실행을 삭제하거나 정상 승패에 합치지 않았다.

| 실행 | 정상 종료 | 중단 | 관찰 |
| --- | --- | --- | --- |
| 기존 v4, 간격 2.5초 | 0승 1패 | 1판 429 | 첫 판 42ply, 호위 배치 1회 |
| 초기 v5, 간격 2.5초 | 1승 3패 | 없음 | 4판 합계 호위 배치 1회. 기력 개선을 입증하지 못함 |
| 압박 자료 추가 v5, 간격 5초 | 없음 | 1판 503 | 36ply까지 호위 배치 4회. 중도 기록이므로 승패 판단 불가 |
| 입력 설명 재구성 v6, 첫 실행 | 없음 | 1판 503 | 2ply 뒤 중단 |
| v6, 간격 10초·API 단계 5초 | 없음 | 1판 시간 초과 | 24ply까지 호위 배치 2회, 마지막 최종 API가 5,006ms에서 중단 |
| v6, API 단계 8초 | 없음 | 1판 시간 초과 | 24ply 뒤 첫 제안 API가 8,005ms에서 중단 |
| v6 고정 설명·로컬 재개 허용 | 0승 4패 | 없음 | 네 판 호위 배치 11회. 한 판은 429 후 재개. 배포 후보 제외 |
| v7 경주·위협을 함께 제시 | 1승 3패 | 없음 | 수비형 흑·백 패배, 전진형 흑 승리·백 패배. 한 판은 429 후 재개 |
| v8 공격 자료·합법 수순 예시 추가 | 0승 4패 | 없음 | 공격 정보를 더 넣어도 개선되지 않음. 배포 후보 제외 |
| 기존 v4 재개 허용 대조군 | 0승 1패 | 1판 시간 초과 | 두 번째 판은 재시도 상한에도 완주하지 못해 4판 비교 미완료 |
| 최종 v9, 새 seed 20260921 | 1승 3패 | 없음 | 수비형 흑 26ply·백 41ply 패배, 전진형 흑 17ply 승리·백 15ply 패배. 3판은 API 오류 후 재개 |

이외 초기 v4·v5 실행에서도 429·시간 초과가 발생했다. 첫 v4 시간 초과는 벤치마크의 다른 모듈 오류 타입 혼용으로 `invalid_response`로 기록됐으며, 벤치마크를 수정했다. 운영 엔진에 자동 재시도나 다른 AI의 대체 착수를 추가하지 않았다.
정상 응답에서 확인한 보고 비용은 0이다. report의 토큰·비용 합계는 완료한 착수 기준이며, 응답 메타데이터 없는 실패 요청까지 비용 0으로 확인했다는 뜻은 아니다.

최종 API 단계의 5초 제한 때문에 전체 턴 예산이 남아도 종료되는 사례를 확인해 제안·최종 API 예산을 각각 8초로 조정했다. 전체 착수 상한 30초·재제안 1회는 그대로 적용하며 모든 단계는 공통 절대 마감을 따른다.
v6 결과에서는 왕 피격 위협을 강조한 반면 경주에서 턴을 잃는 비용이 선택지 설명에 약했다. v7 `mongjin-briefing-3`은 각 제안·최종 선택지에 양쪽의 도달 시점 추정과 상대 응수를 함께 놓는다. 상대도 위협을 만드는 데 한 턴을 써야 한다는 점을 명시한다. 추가 v8 실험도 0승 4패여서 최종 후보 v9에서는 v7 입력으로 복원했다. v9는 새로운 seed 20260921을 사용해 정책을 다시 고치지 않고 확인한다. 같은 상대 종류의 새 난수 조건이므로 새로운 상대 유형에 대한 일반화 검증은 아니다. 최종 네 판은 1승 3패로 끝났다. 기력 향상은 입증하지 못했다. 54회 착수 시도 중 49회가 선택을 완료했고, 실패 5회(429 2회·시간 초과 3회)는 로컬에서만 재시도했다. 세 판이 이 복구를 거쳤다. 완료 착수의 보고 비용 합계는 0, 토큰은 987,082개다.

로컬 벤치마크에만 `--transient-retries 2`를 제공한다. 기본값은 0이고, 429·명시적 503·시간 초과에만 같은 판에서 턴당 최대 2회, 게임당 최대 4회 재요청한다. 재시도 전 30초를 쉬고 무료 기간을 다시 확인한다. 실패한 모든 trace와 `failureCodes`, `retryCount`, `completedAfterRecovery`를 남긴다. 비용 오류·잘못된 응답에는 재시도하지 않는다. 운영 서버의 오류 시 무효 종료 정책은 변경하지 않았다. 복구를 거쳐 완주한 판은 중단 없는 운영 안정성의 증거가 아니다.

## 자동 검사와 재현 자료

- 최종 서버 전체 **218개**, 공통 소스 **80개**, bot **10개**, 합계 **308개** 통과. 서버 최종 검사는 Node 20.20.2에서 실행했다.
- 서버 검사는 운영 DB와 분리한 일회용 PostgreSQL 16을 포함한다. 실제 WebSocket·별도 계산 프로세스의 정상 착수, 오류 시 무효 종료, 대기 중 항복을 검사했다.
- 서버 타입 검사, 루트 타입 검사와 프로덕션 빌드, `git diff --check` 통과. API 단계 예산을 8초로 조정한 뒤 관련 64개 및 실제 WebSocket 통합 3개를 재검사해 통과했다.
- GPT-5.6 Sol의 독립 리뷰에서 발견한 재제안 후보 상한과 증명 재생 검사를 수정했다. 실제 저장 v4 17개·v5 65개 판단 기록도 재생 검증을 통과했다.
- 최종 시범 4판의 99ply와 판단 54개를 재생했다. 정상 선택 49개가 실제 기보 수·적용 후 해시와 일치하고, 종국 승자·사유도 일치했다.
- 모델 설명·판단 자료의 수정은 회귀 검사로 확인했지만, 자동 검사 통과 자체가 기력 향상의 증거는 아니다.

## 최종 판단과 운영 반영

설명·판단 자료와 검증 정확성은 보강했지만, 시범 승률이 좋아졌다고 주장할 근거는 없다. 설명을 늘린 v6·v8은 제외하고, v7 입력을 복원한 v9에 확정 증거 보존·탐색 개선을 함께 반영한다. 로컬 정상 선택 49회의 p95는 2,975ms, 최대 3,860ms다. 실패 시도·재시도 대기·실험 간격을 뺀 값이며 운영 지연 측정이 아니다.

사용자가 요청한 운영 서버 반영을 진행한다. 앱 버전 1.0.8(64), 닉네임, 기존 전적·Elo를 유지한다. 실제 운영 상태·커밋·Render 배포 ID는 로컬 `artifacts/jev/v9-deployment-20260920.json`에 배포 후 확인해 기록한다.
