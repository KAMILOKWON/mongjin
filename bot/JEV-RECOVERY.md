# JEV 랭킹 실험 오류 복구

작성: 2026-09-20. 대국 전략은 `parallel-v13`, 복구 정책은 `retry-v1`이다.

## 수정한 문제

20:38 KST의 운영 대국에서 5회 착수 후 `http_error`가 발생했다. 기존 코드는 이 오류를 영구 중단 사유에 넣어 cooldown이 지나도 신규 매칭을 열지 않았다. 당시 HTTP 상태는 워커 경계를 통과하면서 유실됐으므로 원인이 503이었다고 단정할 수 없다. 오류로 무효 처리한 대국이 메모리의 최근 상대 기록에 남아 같은 이용자의 JEV 재매칭도 막고 있었다.

## 동작

- 네트워크 단절, HTTP 408·429·5xx, 시간 초과, 워커 실행 실패는 일시 오류로 분류한다. 같은 착수 전 상태에서 최대 2회 재시도한다. 대기 시간은 0.5초·1.5초이며 모든 시도와 기록 저장이 기존 수당 30초 제한 및 실험 만료 시각을 공유한다.
- 재시도까지 실패하면 해당 대국을 무효 처리하고 승패·Elo를 변경하지 않는다. 신규 JEV 매칭은 15초 뒤 자동으로 다시 열린다. 연속 실패 시 30초·60초·120초로 늘리며 최대 2분이다. 성공하면 연속 실패와 대기를 초기화한다. 누적 일시 오류 수 때문에 영구 중단하지 않는다.
- 무효 대국은 직전 상대 제외에 사용하지 않는다. 시작 전 최근 상대 목록을 복구하되 같은 프로필의 다른 세션이 추가한 새 대국 기록을 덮어쓰지 않는다. 영속적인 최근 상대 조회는 완료된 대국만 사용한다.
- HTTP 400·401·402·403 등 재시도로 해결할 수 없는 오류, 잘못된 모델 응답, 비용 검증 실패는 계속 중단한다. 실제 HTTP 상태를 응답 본문과 별도로 판단 기록·워커 IPC·health에 보존한다.
- 재시도 전 실패 판단 기록을 저장하고, 성공한 시도의 선택만 한 번 적용한다. 이용자 기권·취소 시 재시도도 취소하며 늦게 도착한 수를 적용하지 않는다.
- 한국 시간 2026-09-25 00:00의 실험 종료와 종료 5분 전 신규 매칭 제한을 유지한다.

## 관측

`/health`의 `jev`에 `recoveryPolicy`, `attempts`, `attemptFailures`, `retries`, `recoveredTurns`, `consecutiveFailures`, `lastError`, `retryAfterMs`를 추가했다. 대기 중 사유는 `transient_cooldown`이고 `cooldownUntil` 이후 자동 해제된다. `http_403`, `billing_unverified` 등은 조치가 필요한 중단과 구분된다. 이 수치는 서버 프로세스 단위이며 완료 대국 수가 아니다.

## 검증

macOS, Node 20.20.2, 로컬 PostgreSQL 16에서 검증했다. JEV API는 오류를 주입한 모의 응답으로 대체했고 운영 프로필·Elo를 변경하는 시험 대국은 만들지 않았다.

- 복구 단위 검사와 기존 실험 검사, 실제 워커를 사용하는 WebSocket 통합 검사: 19/19 통과.
- 전체 `npm test -- --maxWorkers=2`: 434/434, 서버 검사: 270/270, 서버 타입 검사 및 루트 빌드 통과.
- 단발 503 및 네트워크 단절 뒤 같은 대국에서 착수 1회 적용.
- 연속 503의 총 3시도와 실패 기록 3개를 확인하고, 15초 대기 뒤 같은 이용자에게 JEV `MATCH_FOUND`가 다시 오는 것을 확인.
- 실제 HTTP 403에 본문 `status: 503`을 넣어도 재시도 없이 403으로 중단.
- 30초 공유 제한, 만료, 재시도 중 취소, 기권 후 늦은 착수 방지, 무효 대국의 Elo 불변을 확인.

오류가 없는 경우의 후보 생성·평가·선택은 변경하지 않았다. 기존 v13 시범 대국 결과는 [JEV-STRENGTH-RESULTS.md](JEV-STRENGTH-RESULTS.md)에 있다. 외부 서비스의 장애 자체를 없애는 변경은 아니며, 일시 오류 이후 수동 재배포를 기다리는 중단을 방지한다.
